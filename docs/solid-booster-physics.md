# Parallel solid boosters

`RocketSimulation` accepts an optional final constructor argument `SolidBoosterDefinition booster`. Its mass, fuel and thrust describe the aggregate attached booster set, so a symmetric pair uses twice each per-booster mass and thrust. Existing calls without boosters preserve the serial-stage model.

`Launch()` commands ignition. From the next simulation step, attached solids burn at fixed thrust and `massFlow = thrust / (Isp * 9.80665)` until their own propellant is exhausted, even when core throttle is zero. Core thrust and booster thrust add along the vehicle's actual axis. Each consumes its own propellant; both contribute to authoritative mass. The RK4 flight integrator splits at booster burnout and independently brackets core cutoff, including when both events occur during one fixed step. Solids also burn during pad hold-down; as with the existing core model, mass-driven liftoff is reconsidered on the next fixed tick.

`BoosterAttached`, `BoosterPropellantKg` and `BoosterBurning` are public simulation properties. Booster dry mass remains attached after cutoff. `JettisonBoosters()` returns false while fuel remains, after landing, when absent, or after a prior separation. Successful separation discards dry mass with no impulse: position, velocity and mission time are unchanged. `Stage()` retains its existing serial-stage behavior and does not separate boosters. Integration should call booster jettison separately after burnout and must include `BoosterBurning` when deciding whether flight is unpowered.

This is a deliberately limited point-mass approximation: constant motor thrust and Isp rather than pressure-dependent thrust or a measured thrust curve; no individual asymmetric motor states, roll, flex, separation impulse or booster recovery. The core stage's Cd and reference area continue to represent the complete attached vehicle: no additional booster drag area is inferred. A supplied SLS preset using maximum vacuum thrust throughout the burn must disclose that approximation. Do not describe this model as certified vehicle performance.

Run `dotnet run --project Booster.Tests`. Checks cover independent solid ignition at zero core throttle, parallel fuel/mass accounting, core staging while solids burn, two distinct cutoff events within one step, retained dry mass, separation continuity, reset, hold-down consumption and parameter validation. These tests do not establish a successful SLS orbital mission.
